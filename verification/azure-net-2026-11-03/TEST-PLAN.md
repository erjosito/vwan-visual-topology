## 1. Validation Methodology & Architectural Design

We validate the new Azure Networking Simulator (`src/azure-net/`) using the same 5-step empirical discipline established for Virtual WAN:

1. **Use-Case Matrix (UC1–UC5)**: Cover standalone Hub-and-Spoke VNet topologies, VNet peering flags (`allowVirtualNetworkAccess`, `allowForwardedTraffic`, `allowGatewayTransit`, `useRemoteGateways`), UDR tables (`disableBgpRoutePropagation`, `VirtualAppliance`, `None`), Azure Route Server (`ASN 65515`, `branchToBranchTraffic`), Active-Active VPN Gateway (`ASN 65515`) with BGP S2S to an on-premises Branch NVA (`ASN 65100`), Hub BGP NVA (`ASN 65010`), and Private Endpoint `/32` `InterfaceEndpoint` routes (`Disabled` vs `RouteTableEnabled`).
2. **GatewaySubnet Proxy Pattern (`snet-gw-proxy`)**: Because Azure forbids deploying regular probe VMs/NICs inside `GatewaySubnet` (`Microsoft.Network/networkInterfaces` effective-route queries require an attached running VM NIC), the Hub VNet (`vnet-aznet-hub`, `10.100.0.0/16`) includes a dedicated proxy subnet `snet-gw-proxy` (`10.100.4.0/24`) associated with the **exact same route table** (`rt-aznet-gw-subnet`) as `GatewaySubnet` (`10.100.0.0/26`). Querying `az network nic show-effective-route-table` on `nic-vm-gw-proxy` empirically measures the effective routes evaluated by `GatewaySubnet` (system `VNetPeering` routes, BGP routes from VPN/ARS, and return UDRs to the Hub NVA).
3. **Bicep Generation (`exportAzNetBicep`)**: Generate deployable Bicep directly from `samples/azure-net/uc1-hub-spoke-nva-ars-baseline.json`, validate with `az bicep build` and `az deployment group validate`, and deploy to `rg-aznet-sim-lab-20261103`.
4. **Azure Capture & Import (`collect-azure-network.ps1` + `importAzNetCapture`)**: Run the read-only PowerShell collector against `rg-aznet-sim-lab-20261103` (including `-IncludeEffectiveRoutes`), import the resulting capture JSON into the simulator, and verify structural and route-table fidelity.
5. **Pre-Observation Predictions vs Live Azure Diagnostics**: Compare frozen simulator predictions against:
   - `az network nic show-effective-route-table` across `nic-vm-spoke1`, `nic-vm-spoke2`, `nic-vm-hub-nva`, and `nic-vm-gw-proxy`
   - `az network routeserver peering list-learned-routes` and `list-advertised-routes`
   - `az network vnet-gateway list-bgp-peer-status`, `list-learned-routes`, and `list-advertised-routes`
   - NVA BGP daemon (`birdc show route`) and kernel forwarding (`ip route`)
   - End-to-end data-plane probes (`curl` / TCP reachability and NVA traversal verification)
